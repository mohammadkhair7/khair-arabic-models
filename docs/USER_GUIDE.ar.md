## 1. التثبيت

```bash
git clone https://github.com/mohammadkhair7/khair-arabic-models
cd khair-arabic-models
git lfs install && git lfs pull      # يُنزّل أوزان النماذج والبيانات
pip install -e .
```

خطوة `git lfs pull` ضرورية. بدونها تكون ملفات `.pt` و`.jsonl` مجرد مؤشرات
حجمها ١٣٠ بايت، وستفشل جميع النماذج في التحميل.

للتحقق من التثبيت:

```bash
arabicmodels info
```

يجب أن ترى النماذج الأربعة وأمامها `[x]`، مع عدد معاملات كل نموذج، وما إذا كان
لديك كرت رسوميات (GPU). وجود الكرت يجعل العمل أسرع نحو عشرة أضعاف، لكن لا شيء
هنا يستلزمه.

### ما الذي تقدّمه الحزمة

| | ماذا يفعل | متى تستخدمه |
|---|---|---|
| **Diacritizer** | يضيف علامات التشكيل | مساعدات القراءة، تحويل النص إلى كلام، البحث |
| **PosTagger** | يحدّد القسم النحوي لكل كلمة | التحليل اللغوي، الترشيح، الفهرسة |
| **StructureTagger** | يفصل النص إلى رقم / سند / متن / عنوان | تحويل صفحات الحديث إلى سجلات |

## 2. تشغيل النماذج (الاستدلال)

### 2.1 إضافة التشكيل

المهمة الأكثر شيوعًا. هناك طريقتان، واختيار الطريقة الصحيحة أهم من أي إعداد آخر.

```python
from arabicmodels import Diacritizer

d = Diacritizer.load()          # يحمّل النموذج المُوصى به (المدعوم نحويًا)

d.diacritize("قال رسول الله صلى الله عليه وسلم")
# 'قَالَ رَسُولُ اللَّهِ صَلَّى اللَّهُ عَلَيْهِ وَسَلَّمَ'
```

**`diacritize()` يعيد كتابة كل العلامات.** يحذف ما في النص من تشكيل ثم يتنبأ به
كاملًا من جديد. استعمله مع النص العاري من التشكيل.

**`fill_gaps()` يملأ الفراغات فقط.** الكلمات التي تحمل تشكيلًا تبقى كما هي
تمامًا، والآيات القرآنية لا تُمسّ:

```python
d.fill_gaps("قَالَ رسول الله ﴿إنا أعطيناك الكوثر﴾ وقال ابن عمر")
# 'قَالَ رَسُولُ اللهِ ﴿إنا أعطيناك الكوثر﴾ وَقَالَ ابْنُ عُمَرَ'
#  └ بقيت    └ مُلئت           └ لم تُمسّ        └ مُلئت
```

> **أيهما تختار؟** إذا كان مصدرك طبعة مطبوعة ضبط محققها التشكيل، فاستعمل
> `fill_gaps()`؛ فتشكيل المحقق دليلٌ علمي، وتشكيل النموذج ترجيحٌ احتمالي. أما
> إذا كان نصك خاليًا من التشكيل تمامًا فالطريقتان متطابقتان، فاستعمل
> `diacritize()`.

اختيار إصدار النموذج:

```python
Diacritizer.load()             # الإصدار 0.2: حروف + نحو — المُوصى به
Diacritizer.load(pos=False)    # الإصدار 0.1: حروف فقط — أسرع وأقل دقة
Diacritizer.load(device="cpu") # فرض استخدام المعالج حتى مع وجود كرت رسوميات
```

الإصدار 0.2 يحمّل مُعرِب الأقسام النحوية داخليًا بوصفه مستخرِج سمات، فيستهلك نحو
٣١ ميغابايت بدل ٢٠، ويكون أبطأ قليلًا. والمقابل يستحق ذلك: نسبة خطأ ٤٫٤٦٪ مقابل
٥٫١٢٪.

### 2.2 تحديد أقسام الكلام

```python
from arabicmodels import PosTagger

t = PosTagger.load()
t.tag("حدثنا قتيبة بن سعيد قال حدثنا سفيان عن الزهري")
# [('حدثنا', 'verb'), ('قتيبة', 'noun_prop'), ('بن', 'noun'),
#  ('سعيد', 'noun_prop'), ('قال', 'verb'), ('حدثنا', 'verb'),
#  ('سفيان', 'noun_prop'), ('عن', 'prep'), ('الزهري', 'adj')]

t.tags              # قائمة الوسوم الأربعة والعشرين كاملة
t.tag_words([...])  # إذا كان نصك مقسّمًا إلى كلمات مسبقًا
```

### 2.3 تقسيم النص إلى أجزائه

```python
from arabicmodels import StructureTagger

s = StructureTagger.load()
unit = ("1248 - حدثنا محمد بن بشار قال حدثنا يحيى عن عبيد الله قال حدثني نافع "
        "عن ابن عمر ان رسول الله صلى الله عليه وسلم قال من اقتنى كلبا الا كلب "
        "ماشية او ضاري نقص من عمله كل يوم قيراطان")

s.segments(unit)     # مجمّعة في كتل قابلة للقراءة
# [('HNUM',  '1248'),
#  ('ISNAD', '- حدثنا محمد بن بشار قال حدثنا يحيى عن عبيد الله قال حدثني نافع عن ابن عمر ان'),
#  ('MATN',  'رسول الله صلى الله عليه وسلم قال من اقتنى كلبا الا كلب ماشية او ضاري نقص من عمله كل يوم قيراطان')]

s.tag(unit)          # زوج (كلمة، وسم) لكل كلمة
s.spans(page_text)   # مواضع الأحرف [بداية، نهاية، وسم] — للصفحات الكاملة
```

استعمل `segments()` حين تريد قراءة النتيجة، و`tag()` حين تريد المعالجة كلمةً
كلمة، و`spans()` حين تحتاج إلى تظليل النص الأصلي دون تعديله — فالمواضع تشير
مباشرةً داخل النص الذي مرّرته.

#### تقسيم الإسناد إلى رواته

النموذج يحدّد الإسناد، والقواعد تقسّمه. أعِد إليها مقطع `ISNAD` كما هو:

```python
chain = next(t for label, t in s.segments(unit) if label == "ISNAD")

for i, hop in enumerate(s.narrators(chain), start=1):
    print(i, chain[hop.verb_start:hop.verb_end], "-", chain[hop.start:hop.end])
# 1 حدثنا - محمد بن بشار
# 2 حدثنا - يحيى
# 3 عن - عبيد الله
# 4 حدثني - نافع
# 5 عن - ابن عمر
```

اقرأ الأسماء من المواضع لا من `hop.mention`؛ فـ`mention` مُوحَّد الرسم للمطابقة،
فتعود `عَائِشَة` في النسخة المشكولة على صورة `عاءشه`، بينما
`chain[hop.start:hop.end]` هو رسم المصدر نفسه بحركاته. أمّا الألقاب
(`رضي الله عنها`، `صلى الله عليه وسلم`) فهي نعوت لا أسماء، وتُترك خارج الموضع.

وتمرير مقطع `ISNAD` الذي حدّده النموذج مقصود: فـ`parse_isnad` يستأنف تحديد
نهاية الإسناد بنفسه وقد يقف في موضع آخر، فيظهر في الصفحة راوٍ خارج الإسناد
المرسوم بجانبه.

الوسوم الأربعة هي: `HNUM` (رقم الحديث المطبوع)، و`ISNAD` (سلسلة الإسناد)،
و`MATN` (متن الحديث)، و`HEADING` (عنوان باب أو كتاب).

### 2.4 من سطر الأوامر

للملفات الكاملة، يغنيك سطر الأوامر عن كتابة أي كود:

```bash
# إضافة التشكيل إلى ملف مع الحفاظ على تشكيله الموجود
arabicmodels tashkeel annotate book.txt --pos --out book.vocalized.txt

# إعادة كتابة التشكيل كاملًا بدلًا من ذلك
arabicmodels tashkeel infer --file book.txt --pos > book.vocalized.txt

# إعراب ملف على هيئة كلمة/وسم
arabicmodels pos infer --file corpus.txt > tagged.txt

# بنية عدة صفحات على هيئة مواضع JSON
arabicmodels structure spans page1.txt page2.txt --out spans.json

# أمر سريع في سطر واحد
arabicmodels tashkeel infer --text "قال رسول الله" --pos
```

الأمر `annotate` يعالج كل ملف ويطبّق الدمج الذي يملأ الفراغات فقط، أما `infer`
فيعيد كتابة كل شيء. أضف `--no-protect-quran` إلى `annotate` إذا كنت **تريد**
فعلًا إضافة التشكيل داخل ﴿…﴾.

### 2.5 السرعة

حمّل النموذج مرة واحدة وأعد استعماله؛ فالتكلفة في التحميل لا في التشغيل:

```python
d = Diacritizer.load()                      # مرة واحدة هنا
results = [d.diacritize(t) for t in texts]  # لا داخل الحلقة
```

وللمهام الكبيرة جدًا استعمل سطر الأوامر مع عدة ملفات دفعة واحدة، أو مرّر
`device="cuda"` إن توفر كرت رسوميات.

## 3. بياناتك: الصيغة والمحتوى

يهمّك هذا القسم إن كنت تنوي التدريب أو الضبط الدقيق. تجاوزه إن كنت تريد تشغيل
النماذج الجاهزة فحسب.

جميع مجموعات البيانات بصيغة **JSONL**: كائن JSON واحد في كل سطر، بترميز UTF-8،
دون مصفوفة خارجية ودون فواصل زائدة.

### 3.1 الصيغ الثلاث

**التشكيل** — `tashkeel.jsonl`. حقل واحد: النص **مع** تشكيله. التشكيل هو
الجواب، وأداة التدريب تجرّده لتصنع السؤال.

```json
{"text": "حَدَّثَنَا قُتَيْبَةُ بْنُ سَعِيدٍ قَالَ حَدَّثَنَا سُفْيَانُ", "split": "train"}
```

**أقسام الكلام** — `pos.jsonl`. كلمات ووسومها، بالطول نفسه، متقابلة موضعًا بموضع.

```json
{"tokens": ["حدثنا", "قتيبة", "بن", "سعيد"], "tags": ["verb", "noun_prop", "noun", "noun_prop"], "split": "train"}
```

**البنية** — `indexing.jsonl`. نوعان من السطور: سطر الحديث يعطي موضع الحرف الذي
ينتهي عنده السند ويبدأ المتن، وسطر العنوان يُوسم كل كلمة فيه بـ `HEADING`.

```json
{"text": "1248 - حدثنا محمد بن بشار ... ان رسول الله قال من اقتنى كلبا", "sanad_end": 80, "split": "train"}
{"text": "باب فضل من استبرأ لدينه", "kind": "heading", "split": "train"}
```

قيمة `split` هي `"train"` أو `"dev"` أو `"test"`. وإذا بنيت بياناتك بالسكربت
المرفق فستُملأ تلقائيًا.

### 3.2 كيف ينبغي أن يكون **المحتوى**

ضبط الصيغة سهل، لكن المحتوى هو موضع فشل المشاريع. لكل مهمة شرط حقيقي:

| المهمة | يجب أن يكون نصك… | لأن |
|---|---|---|
| **التشكيل** | مُشكّلًا فعلًا، وبكثافة | التشكيل **هو** التصنيف المستهدف. النص غير المشكول لا يعلّم شيئًا |
| **البنية** | حديثًا واحدًا في كل سجل، بصِيَغ الإسناد المعتادة (حدثنا / أخبرنا / عن) | أداة التصنيف محلّل قواعدي مضبوط على هذه الصيغ |
| **أقسام الكلام** | نثرًا عربيًا متصلًا عاديًا | المعلّم يحلّل كلمةً كلمة |

والعتبات التي يفرضها بانِي البيانات:

- **التشكيل:** لا تُقبل النافذة إلا إذا بلغت **٦٠ حرفًا عربيًا فأكثر** وكثافة
  **٠٫٦ علامة لكل حرف فأكثر**. الصفحة نصف المشكولة تُرفض. وهذا مقصود: التدريب
  على تشكيل متفرق يعلّم النموذج أن يترك الحروف عارية.
- **البنية:** سجلات بين **١٥٠ و٤٠٠٠ حرف**، وأن يعطي محلّل الإسناد ثقة **٠٫٩
  فأكثر**. وعادةً يجتاز ذلك ٦٠–٩٩٪ من الأحاديث الحقيقية بحسب الطبعة.
- **أقسام الكلام:** سجلات بين **٢٠٠ و٢٥٠٠ حرف** وفيها ٨ كلمات على الأقل.

وكم تحتاج من البيانات؟ إرشاد تقريبي من المجموعات المرفقة:

| المهمة | المرفق | الحد الأدنى المفيد للضبط الدقيق |
|---|---:|---:|
| التشكيل | ٧٠٬٠٠٠ نافذة | نحو ٢٬٠٠٠ نافذة |
| البنية | ٤٨٬٠٠٠ سطر | نحو ٢٬٠٠٠ سطر |
| أقسام الكلام | ٤٬٠٠٠ مقطع | نحو ٥٠٠ مقطع |

### 3.3 بناء مجموعات بيانات من نصوصك

ضع نصك في ملف `.txt` (أو مجلد من الملفات)، أو في ملف `.jsonl` من كائنات
`{"text": "..."}`، ثم:

```bash
# التشكيل — من كتب مشكولة
python scripts/build_datasets.py --task tashkeel \
    --input mybooks/ --record blank-line --out-dir mydata/

# البنية — حديث في كل سطر، مع ملف بعناوين الأبواب
python scripts/build_datasets.py --task indexing \
    --input units.jsonl --headings titles.txt --out-dir mydata/

# أقسام الكلام — تحتاج إلى تثبيت المعلّم
pip install "arabicmodels[teacher]" && camel_data -i morphology-db-msa-r13
python scripts/build_datasets.py --task pos --input units.jsonl --out-dir mydata/
```

ويحدّد `--record` كيف يقطع السكربت ملف `.txt` العادي إلى سجلات:

| `--record` | كل سجل هو… | مناسب لـ |
|---|---|---|
| `line` (الافتراضي) | سطر واحد | حديث في كل سطر |
| `blank-line` | فقرة بين سطرين فارغين | الكتب المقسّمة إلى فقرات |
| `file` | الملف كله | مستند واحد في كل ملف |

ويطبع السكربت ما أبقاه، وهذا أول فحص للسلامة:

```
building tashkeel dataset (text as labeler)…
mydata/tashkeel.jsonl: 300 samples {'train': 260, 'test': 20, 'dev': 20}
```

فإن حصلت على **٠ عينة** فمحتواك لم يجتز المرشّحات — ومع التشكيل يعني ذلك دائمًا
تقريبًا أن النص ليس مشكولًا بما يكفي.

## 4. التدريب من الصفر

لا تدرّب من الصفر إلا إذا كان هدفك مختلفًا اختلافًا حقيقيًا: مجموعة وسوم جديدة،
أو نوع من العربية بعيد عن النثر الحديثي الكلاسيكي. وفيما عدا ذلك استعمل
[الضبط الدقيق](#5-الضبط-الدقيق-fine-tuning)، فهو أسرع ويحتاج بيانات أقل بكثير.

```bash
arabicmodels structure train --epochs 3          # نحو ١٨ دقيقة على RTX 3080
arabicmodels pos       train --epochs 4          # نحو دقيقة
arabicmodels tashkeel  train --epochs 3          # نحو ٧ دقائق (الإصدار 0.1)
arabicmodels tashkeel  tag-data                  # يهيّئ بيانات الإصدار 0.2
arabicmodels tashkeel  train --pos --epochs 3    # نحو ٧ دقائق (الإصدار 0.2)
```

الترتيب مهم للإصدار 0.2؛ فهو يستعمل مخرجات نموذج أقسام الكلام سمةً، فدرّب
`pos` أولًا، ثم `tag-data`، ثم `--pos`.

وعلى بياناتك أنت، مع الحفظ في مكان آمن:

```bash
arabicmodels tashkeel train \
    --data mydata/tashkeel.jsonl \
    --out  mymodels/tashkeel.pt \
    --epochs 3
```

> **تحذير.** بدون `--out` فإن التدريب **يستبدل ملف النموذج المرفق** في مجلد
> `models/`. مرّر `--out` دائمًا ما لم تكن تقصد استبداله. وإن استبدلته سهوًا:
> `git checkout models/`.

وهكذا تبدو الجلسة السليمة — الخسارة تنخفض ومقياس التطوير يتحسّن:

```
device=cuda data=tashkeel.jsonl train=63015 dev=3445 vocab=77 params=5,146,256
checkpoint -> mymodels/tashkeel.pt
epoch 1: loss 0.2318 dev DER(all) 0.0705 DER(marked) 0.0602 (132s)
epoch 2: loss 0.1487 dev DER(all) 0.0563 DER(marked) 0.0471 (131s)
epoch 3: loss 0.1252 dev DER(all) 0.0502 DER(marked) 0.0409 (130s)
  saved -> mymodels/tashkeel.pt
```

ولا تُحفظ إلا أفضل دورة، فلا تستطيع دورة أخيرة سيئة أن تفسد ملف نموذجك.

ثم قِس على بيانات لم يرها النموذج قط:

```bash
arabicmodels tashkeel eval --data mydata/tashkeel.jsonl --ckpt mymodels/tashkeel.pt
```

## 5. الضبط الدقيق (fine-tuning)

**هذا هو المطلوب في أغلب الحالات.** الضبط الدقيق ينطلق من نموذج جاهز ويوجّهه
نحو نصوصك؛ يحتاج جزءًا يسيرًا من البيانات وجزءًا يسيرًا من الوقت، ويحتفظ بكل ما
تعلّمه النموذج عن العربية.

### 5.1 الأمر الواحد

```bash
arabicmodels tashkeel train \
    --init-from models/tashkeel_bilstm.pt \
    --data      mydata/tashkeel.jsonl \
    --out       mymodels/tashkeel-mine.pt \
    --epochs 2 --lr 2e-4
```

ثلاثة أمور تستحق الانتباه:

- `--init-from` هو ما يحوّل التدريب إلى ضبط دقيق.
- `--out` يحفظ النموذج الأصلي من الاستبدال.
- `--lr 2e-4` **أقل بعشر مرات** من معدّل التدريب من الصفر. والضبط الدقيق بمعدل
  مرتفع يمحو ما كان النموذج يعرفه. وهذا أشيع خطأ على الإطلاق.

### 5.2 لماذا ينجح — بالقياس

البيانات نفسها (٢٬٢٥٧ سطرًا)، ودورة واحدة، وكل شيء آخر ثابت:

| | المعجم | خطأ التطوير (DER) |
|---|---:|---:|
| من الصفر | ٦٤ حرفًا، أُعيد بناؤه من المجموعة الصغيرة | **٢٤٫٣٠٪** |
| ضبط دقيق من النموذج المرفق | ٧٧ حرفًا، أُعيد استعماله | **٣٫٠٨٪** |

فرقٌ بثمانية أضعاف من خيار واحد. فالمجموعات الصغيرة لا تستطيع تعليم العربية من
العدم، وإنما تستطيع تعديل نموذج يعرفها أصلًا.

ولاحظ عمود المعجم. عند الضبط الدقيق يأتي معجم الحروف ومعجم الوسوم **من ملف
النموذج** لا من بياناتك؛ لأن التضمين (embedding) الذي تعلّمه النموذج لمعجم معيّن
لا معنى له مع معجم آخر. وتطبع الأداة سطرًا يؤكد ذلك:

```
fine-tuning from models/tashkeel_bilstm.pt — vocabularies reused from the
checkpoint, not rebuilt from the data
```

ويترتب على ذلك أمر عملي: الحروف الموجودة في بياناتك والغائبة عن معجم النموذج
تصير `<unk>`. وفي أقسام الكلام لا يمكن تعلّم وسوم خارج الأربعة والعشرين أصلًا،
وتنبّهك الأداة إلى ذلك:

```
warning: 2 tag(s) absent from the vocabulary will train as <unk>: ['dialect', 'foreign']
```

فإن احتجت وسومًا جديدة فدرّب من الصفر بدلًا من ذلك.

### 5.3 الإعدادات التي تنجح

| الإعداد | من الصفر | الضبط الدقيق |
|---|---|---|
| `--lr` | 1e-3 (و2e-3 للتشكيل) | **2e-4**، أو 1e-4 مع البيانات الصغيرة جدًا |
| `--epochs` | ٣–٤ | **١–٣** — وما زاد يؤدي إلى الإفراط في المطابقة |
| البيانات المطلوبة | عشرات الآلاف من السطور | نحو ٢٬٠٠٠ سطر تكفي غالبًا |
| `--init-from` | يُترك | **مطلوب** |
| `--out` | مُستحسن | **مطلوب عمليًا** |

وراقب مقياس التطوير بين الدورات؛ فإن توقف عن التحسن فأوقف التدريب، إذ تكون
أفضل دورة قد حُفظت بالفعل.

### 5.4 الضبط الدقيق للنموذجين الآخرين

```bash
# البنية، على أحاديثك الموسومة
arabicmodels structure train --init-from models/indexing_wordtagger.pt \
    --data mydata/indexing.jsonl --out mymodels/structure-mine.pt \
    --epochs 2 --lr 2e-4

# أقسام الكلام
arabicmodels pos train --init-from models/pos_wordtagger.pt \
    --data mydata/pos.jsonl --out mymodels/pos-mine.pt \
    --epochs 2 --lr 2e-4
```

### 5.5 استعمال نموذجك المضبوط

من سطر الأوامر، وجّه `--ckpt` إليه:

```bash
arabicmodels tashkeel infer --text "قال رسول الله" --ckpt mymodels/tashkeel-mine.pt
arabicmodels tashkeel eval  --data mydata/tashkeel.jsonl --ckpt mymodels/tashkeel-mine.pt
```

ومن بايثون، مرّر `path=`:

```python
d = Diacritizer.load(pos=False, path="mymodels/tashkeel-mine.pt")
s = StructureTagger.load(path="mymodels/structure-mine.pt")
p = PosTagger.load(path="mymodels/pos-mine.pt")
```

ومع مُشكّل الإصدار **0.2** المضبوط يمكنك أيضًا استبدال مستخرِج السمات النحوية
بالخيار `--pos-ckpt`.

## 6. سيناريوهات الاستخدام

### السيناريو أ — تشكيل كتاب مشكول جزئيًا

*لديك طبعة ضبط محققها بعض الكلمات، وتريد إتمام الباقي دون إضاعة عمل المحقق.*

```bash
arabicmodels tashkeel annotate chapter1.txt chapter2.txt \
    --pos --out vocalized.txt
```

يملأ `annotate` الكلمات العارية تمامًا فقط، ويترك الآيات القرآنية. وتحقّق قبل
أن تثق بالمعالجة الكاملة:

```python
from arabicmodels import Diacritizer, split_marks
d = Diacritizer.load()
original = open("chapter1.txt", encoding="utf-8").read()
result = d.fill_gaps(original)
assert split_marks(result)[0] == split_marks(original)[0]  # لم يتغير أي حرف
```

هذا التحقق جدير بالتشغيل على أي دفعة، فهو يثبت أن التغيير وقع في العلامات وحدها.

### السيناريو ب — تكييف المُشكّل على نوع نصي مختلف

*نصوصك كلاسيكية لكنها ليست حديثية — فقه أو تفسير أو شعر — والدقة دون المتوقع.*

١. اجمع نصًا مشكولًا من ذلك النوع، واستهدف ٢٬٠٠٠ نافذة فأكثر.
٢. ابنِ مجموعة البيانات:
```bash
python scripts/build_datasets.py --task tashkeel \
    --input myfiqh/ --record blank-line --out-dir mydata/
```
٣. اضبط ضبطًا لطيفًا:
```bash
arabicmodels tashkeel train --init-from models/tashkeel_bilstm.pt \
    --data mydata/tashkeel.jsonl --out mymodels/fiqh.pt --epochs 2 --lr 2e-4
```
٤. قارن القديم بالجديد على مجموعة اختبارك **أنت**:
```bash
arabicmodels tashkeel eval --data mydata/tashkeel.jsonl   # النموذج المرفق
arabicmodels tashkeel eval --data mydata/tashkeel.jsonl --ckpt mymodels/fiqh.pt
```

فإن لم يتحسن الرقم بعد الضبط فالأرجح أنك استعملت معدل تعلّم مرتفعًا أو دورات
كثيرة.

### السيناريو ج — تحويل صور الصفحات إلى سجلات منظمة

*لديك صفحات مقروءة ضوئيًا وتريد كل حديث سجلًا مستقلًا بسنده ومتنه منفصلين.*

```python
from arabicmodels import StructureTagger

s = StructureTagger.load()
page = open("page_042.txt", encoding="utf-8").read()

for start, end, label in s.spans(page):
    print(label, repr(page[start:end][:60]))
```

يعطي `spans()` مواضع الأحرف داخل الصفحة الأصلية، فتستطيع تخزين البنية إلى جانب
النص دون تعديله. ولتخطّي المقدمات والفهارس تلقائيًا:

```python
from arabicmodels.indexing import usable_spans
spans = s.spans(page)
if usable_spans(spans):
    ...   # صفحة أحاديث حقيقية
```

وتُعالَج الصفحات في كتل من ٢٢٠ كلمة، فتوقّع خطأً عارضًا عند حدود الكتل في
الصفحات الطويلة جدًا.

### السيناريو د — بناء فهرس بحث واعٍ بالنحو

*تريد بحثًا يميّز الفعل «صام» من الاسم العلم.*

```python
from arabicmodels import PosTagger, normalize_arabic

tagger = PosTagger.load()
for doc_id, text in corpus:
    for word, tag in tagger.tag(text):
        index.add(doc_id, normalize_arabic(word), tag)
```

وتوحّد `normalize_arabic` صور الرسم (أ إ آ ← ا، ة ← ه، ى ← ي) فيطابق الاستعلام
الكلمة مهما كُتبت.

### السيناريو هـ — التدريب على متن ليس حديثيًا أصلًا

*لديك متن كلاسيكي كبير مشكول من نوع آخر.*

التشكيل ينتقل جيدًا، فالعلامات هي التصنيف أيًّا كان النوع؛ فابنِ مجموعة بيانات
واضبط ضبطًا دقيقًا (السيناريو ب). أما البنية فلا تنتقل: أداة تصنيفها محلّل
إسناد حديثي لن يجد شيئًا في الأنواع الأخرى. ولتقسيم نوع آخر من المستندات
ستحتاج إلى حدودك أنت بصيغة `indexing.jsonl`، ثم التدريب من الصفر.

### السيناريو و — التشغيل على خادم بمعالج فقط

كل شيء يعمل دون تغيير، مع بطء يقارب عشرة أضعاف.

```python
d = Diacritizer.load(pos=False, device="cpu")   # الإصدار 0.1 أخفّ
```

وللمهام الكبيرة فضّل سطر الأوامر على حلقة بايثون، ومرّر ملفات كثيرة دفعة واحدة
ليُحمَّل النموذج مرة واحدة. أما الذاكرة فنحو ٢٠ ميغابايت للإصدار 0.1 و٣١ للإصدار
0.2.

## 7. مرجع الخيارات

### خيارات مشتركة في كل أمر `train`

| الخيار | الافتراضي | المعنى |
|---|---|---|
| `--data JSONL` | المجموعة المرفقة | بيانات التدريب |
| `--out CKPT` | **يستبدل الملف المرفق** | مكان الحفظ |
| `--init-from CKPT` | معطّل | ضبط دقيق انطلاقًا من هذا الملف |
| `--epochs N` | ٣ (وأقسام الكلام ٤) | عدد المرور على البيانات |
| `--batch-size N` | ٣٢ (والتشكيل ٦٤) | خفّضه عند نفاد الذاكرة |
| `--lr FLOAT` | 1e-3 (والتشكيل 2e-3) | استعمل 2e-4 في الضبط الدقيق |
| `--limit N` | الكل | يقرأ أول N سطرًا فقط — مفيد للتجربة السريعة |
| `--seed N` | ١٣ | بذرة العشوائية |

### الأمر `eval`

| الخيار | المعنى |
|---|---|
| `--data JSONL` | التقييم على مجموعة اختبارك |
| `--ckpt CKPT` | تقييم ملف نموذج محدد |
| `--limit N` | قراءة أول N سطرًا فقط |

### الأوامر `infer` و`annotate` و`spans`

| الخيار | يخصّ | المعنى |
|---|---|---|
| `--text "..."` | infer | نص مباشر |
| `--file PATH` | infer | القراءة من ملف |
| `--out PATH` | annotate و spans | كتابة النتائج في ملف |
| `--ckpt CKPT` | الكل | استعمال نموذجك أنت |
| `--pos` | tashkeel | استعمال الإصدار 0.2 المدعوم نحويًا |
| `--pos-ckpt CKPT` | tashkeel | مستخرِج السمات النحوية الخاص بك |
| `--no-protect-quran` | annotate | التشكيل داخل ﴿…﴾ أيضًا |

### واجهة بايثون

| الاستدعاء | يُرجع |
|---|---|
| `Diacritizer.load(pos=True, device=None, path=None)` | مُشكّلًا |
| `.diacritize(text)` | النص بتشكيل مُعاد حسابه كاملًا |
| `.fill_gaps(text, protect_quran=True)` | النص بملء الكلمات العارية فقط |
| `PosTagger.load(device=None, path=None)` | مُعرِبًا |
| `.tag(text)` / `.tag_words(words)` | `[(كلمة، وسم)]` / `[وسم]` |
| `.tags` | الوسوم الأربعة والعشرين |
| `StructureTagger.load(device=None, path=None)` | مُقسِّمًا |
| `.tag(text)` / `.segments(text)` / `.spans(text)` | لكل كلمة / مجمّعة / مواضع |
| `.narrators(isnad_text)` | رواة إسناد واحد على هيئة `Hop` |
| `normalize_arabic(text)` | النص بصور رسم موحّدة |
| `strip_diacritics(text)` | حذف الحركات والتطويل مع بقاء الحروف كما هي |
| `split_marks(text)` / `apply_marks(text, labels)` | نزع التشكيل / إعادته |
| `parse_isnad(text)` | تحليل الإسناد القواعدي |
| `narrator_hops(chain)` | رواة نصٍّ مقطوعٍ بأنه إسناد |

## 8. حل المشكلات

**`checkpoint not found` أو `FileNotFoundError`**
لم تُنزَّل الأوزان. نفّذ `git lfs install && git lfs pull` ثم `arabicmodels info`
للتأكد.

**`no usable training rows in …`**
لم تجتز بياناتك المرشّحات. في التشكيل يكون النص غالبًا غير مشكول بما يكفي
(يلزم ٠٫٦ علامة لكل حرف)، وفي البنية قد لا تكون السجلات أحاديث مفردة. راجع
القسم ٣٫٢.

**`--pos needs rows with a 'tags' field`**
مُشكّل الإصدار 0.2 يحتاج بيانات موسومة نحويًا. نفّذ
`arabicmodels tashkeel tag-data` أولًا.

**`build_datasets.py` أنتج ٠ عينة**
السبب نفسه أعلاه. اطبع بضعة سجلات من بياناتك وقارنها بأمثلة القسم ٣٫١.

**`CAMeL teacher unavailable`**
لا يحتاجه إلا بانِي بيانات أقسام الكلام:
`pip install "arabicmodels[teacher]"` ثم `camel_data -i morphology-db-msa-r13`.

**الضبط الدقيق جعل النموذج أسوأ**
معدل التعلّم مرتفع أو الدورات كثيرة. جرّب `--lr 1e-4 --epochs 1`، وراقب مقياس
التطوير بعد كل دورة لا في النهاية فقط.

**نفاد ذاكرة كرت الرسوميات**
خفّض `--batch-size` (جرّب ١٦، أو ٣٢ للتشكيل)، أو أضف `--limit` أثناء التجريب.

**المخرجات تبدو صحيحة لكنها لا تطابق مرجعي**
تُكتب الشدة قبل الحركة، وهو ما يُعرض مطابقًا للترتيب المعياري لكنه تسلسل بايتات
مختلف. وحّد الطرفين: `unicodedata.normalize("NFC", text)`.

**كلمة فقدت ألفها الخنجرية (هَٰذَا ← هَذَا)**
هذا متوقع. الرمز U+0670 خارج الأصناف الستة عشر ولا تنتجه النماذج أبدًا. انظر
[`MODEL_CARDS.md`](MODEL_CARDS.md).

**استبدلت ملف نموذج مرفق**
`git checkout models/` يستعيده.
